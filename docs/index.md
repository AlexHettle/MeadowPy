# MeadowPy Documentation

This folder is the standalone documentation set for MeadowPy.

Start here:

- [Getting Started](getting-started.md): install MeadowPy, run setup, launch
  the app, and run a first Python file.
- [User Guide](user-guide.md): learn the editor, file explorer, run/debug
  tools, Output panel, Terminal panel, Problems panel, search, examples,
  preferences, and AI features.
- [AI Setup](ai-setup.md): configure Ollama, choose a model, understand local
  AI behavior, and troubleshoot AI setup.
- [Troubleshooting](troubleshooting.md): solve common setup, launch, editor,
  run, debug, lint, search, and AI problems.
- [Shortcuts](shortcuts.md): view keyboard shortcuts and contextual input
  shortcuts.

Maintainer docs:

- [Development Guide](development.md): set up a development environment,
  understand repo layout, and follow coding expectations.
- [Testing](testing.md): run the automated test suite, targeted tests, coverage,
  and UI smoke checks.
- [Architecture](architecture.md): understand app startup, controllers, core
  services, editor behavior, resource loading, run/debug/lint/search/AI flows,
  and ownership boundaries.
- [Release Process](release-process.md): prepare, verify, document, tag, and
  follow up on releases.

## Documentation Maintenance

When MeadowPy changes, update docs in the same change whenever possible:

- User-facing workflows belong in [User Guide](user-guide.md).
- Setup and launch changes belong in [Getting Started](getting-started.md).
- AI behavior belongs in [AI Setup](ai-setup.md).
- Common errors belong in [Troubleshooting](troubleshooting.md).
- Shortcut changes belong in [Shortcuts](shortcuts.md).
- Development workflow changes belong in [Development Guide](development.md).
- Test command or coverage changes belong in [Testing](testing.md).
- Ownership or flow changes belong in [Architecture](architecture.md).
- Release workflow changes belong in [Release Process](release-process.md).
